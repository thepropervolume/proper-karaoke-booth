# The Proper Volume Karaoke

Version **0.2.0**, a local-first desktop karaoke rehearsal application. Development updates use `0.x.y`; `1.0.0` is reserved for the approved official release. This is early development software, not yet ready to run a live show. Core local playback does not require an account or internet connection after installation; YouTube downloads require internet; saved songs play offline.

## Run or install

Windows 0.2.0 installer and ZIP packages have been built and an isolated packaged launch/restart passed. The final delivery rebuild and actual install/upgrade/uninstall checks are still pending. Linux packaging is being verified separately; macOS packages require a Mac. See [installation and packaging](docs/installation.md). Private catalog configuration, media, yt-dlp and FFmpeg are not bundled.

For development, prerequisites are Node.js and npm. Automated rehearsals have run on Linux and Windows with Electron 45; macOS and physical audio/display devices still need testing. Install dependencies once (internet required), then build and start:

```bash
npm ci
npm run build
npm start
```

Electron may download its runtime on first use. The app keeps its SQLite database in Electron's user-data directory, outside this checkout; imported media remains at its original location. Use **Back up show…** to save a checked show database while the app is running. Choose a new filename; the app will not replace existing files. Video files, settings, keybindings, logos and other external files are not included. Back those up separately, and choose a private destination because the database contains singer information and library paths. Restore in the app is not available yet.

## Rehearse

1. Use **Import Video File** or **Import Custom Directory** to add MP4 files. A directory scan includes subfolders; duplicate contents are skipped and originals stay in place. The import panel shows current-file progress and paged results. You can cancel while continuing to use playback controls; songs already imported stay in the library. The current file is reported as cancelled and files not yet discovered are not processed. Results remain visible until the next import or app exit; folder totals grow during the scan.
2. Double-click a song, choose an existing singer or enter a new name, and select **Add to Queue**. A single click only selects the song. Requests are auto-approved by default; with moderation enabled, accept or reject them in **Requests**. In Singer Rotation, select an accepted waiting request and use **Promote selected** to move it ahead of other waiting requests without displacing a staged song. The host can inspect recent rejected, withdrawn, removed, completed and skipped requests in **Request history**.
3. Open **Singer Display** and choose the monitor. Use the **Toggle singer display fullscreen** icon to expand or restore the singer window. **Play/Pause** stages the next eligible song if necessary and starts it, or pauses/resumes an active performance. Stop and confirmed skip are available. Focus a waiting item in Singer Rotation and press **Delete** to remove it; the active performance is not removed.
4. On restart the interrupted show is restored paused; open the singer display and deliberately resume. Stopping returns the current request to the queue; skipping consumes its turn.
5. Use **Back up show…** in the workspace to save a database snapshot to a new file. If temporary cleanup needs attention, use **Retry backup cleanup**; the message says whether the backup was already saved. Filesystem support for hard links is required; some external or network drives may not support it.

Use the search icon or **Ctrl+F** to open library search, including from the singer display. Search matches title, artist, filename, DJ code and track number; the Sort and Filter controls narrow or order the visible library. Filenames are available only in the host window. **Space** runs Play/Pause in either window when the host is not typing or operating a focused control. See [keyboard shortcuts](docs/keyboard-shortcuts.md) for defaults and customization.

**Karaoke Nerds** in the host sidebar can search the shared catalog by artist or title. Open **Preferences → Shared Karaoke Nerds Catalog** to choose a private client configuration, check the connection and save the search preference. The server at `https://apps.thepropervolume.com` uses a dedicated MySQL catalog seeded from the recovered 64,261-record snapshot; it currently exposes 64,261 valid, unique YouTube recordings, including unmapped brands. Upstream freshness is unknown and automatic refresh is disabled. The Windows client has now passed live HTTPS status and search checks against the deployed service, plus durable offline-cache reuse after a simulated connection failure. The implemented client can retain up to 100 previously successful queries (20 MiB) for clearly labeled offline reuse. New offline queries need a prior matching result.

For a result with a supported YouTube link, **Add to Library** starts a permanent yt-dlp download; you can also enter a URL, title and artist. The library keeps its YouTube service label and shows whether it is saved locally. Once ready, double-click and choose a singer normally. Playback uses the local player, selected audio output, volume and timeline, including offline. Completion never autoplays: press Play when ready. **Download Video / Retry** is available on a library song's right-click menu; only one download runs at a time. See [YouTube playback](docs/youtube-streaming.md). The separate Preview YouTube command remains an internet-only embedded preview with system audio and no downloading.

Right-click a library song to add it to a playlist or the queue, edit its local metadata, or show the source file in the file manager. **Playlists** contains host-managed singer lists, KJ Picks, artist browsing and completed/skipped performance history recorded from this version onward; earlier performances are not backfilled. In History, search by singer, artist or title and optionally filter by singer. Use **Export matching history…** to save those records; choose a new filename because existing files are never overwritten. Export needs a filesystem that supports hard links. Choose a private destination: on Windows the file inherits that folder’s permissions. Values that could be interpreted as spreadsheet formulas are prefixed with an apostrophe; spreadsheet applications may change this protection when saving or reopening the CSV. Genre browsing is not available until genre metadata exists. If a song is missing, use **Can't Find a Song?**; the request is saved for review and does not enter the rotation. In **Requests**, the host can mark unavailable-song requests Pending, Reviewing, Fulfilled or Declined. See the [singer guide](docs/singer-guide.md).

If a source video moves, right-click the song and choose **Relink File…**, then select the original MP4. The replacement must match the complete imported file fingerprint; a different or edited file is refused, and neither file is changed. Reimport a different recording as a new song. Before a song starts, the app checks its full fingerprint and refuses a missing or changed source; large videos or slow drives can take longer to start. A normal pause/resume uses a quick identity check and rechecks the full file if it changed or the app restarted. The app cannot guarantee detection of a file modified after the check or during playback.

Experimental **Remote Queueing** is off until a host explicitly opens a local room. It requires a private IPv4 interface, a hostname resolving only to that interface, and a certificate and private key already trusted by Node and singers' devices. In Preferences, select the interface and TLS files, open the room, create an invitation and share its link privately. Singers can join, browse loaded songs, request one or ask for a missing song. They can withdraw their own pending or accepted requests; staged and playing songs remain locked. Close the room to revoke invitations and guest access. The room is not restarted automatically. Internet access, certificate provisioning and IPv6 hosting are not implemented; browser/phone trust, real venue DNS, firewall and device behavior still require physical testing. See [remote host controls](docs/remote-host-controls.md).

Choose an audio output in **Preferences → Audio Controls**, or use the system default. Changing the output pauses an active song. The player mutes and pauses on a reported device change, then requires deliberate resume; real device unplugging and OS-level rerouting still need physical verification. If the singer display closes or disconnects during playback, the host is warned and can reopen it before resuming. Disconnecting a display previously used by the singer window may conservatively pause playback even after the window has moved elsewhere. Playback errors are reported to the host, including a suggestion to check the file or codec. Other MP4 codecs may not be playable even though the container is `.mp4`.

## Preferences

Use the palette icon in the host toolbar to cycle the primary accent through **blue**, **pink**, and **purple**. The choice is saved immediately and applies in both Day and Night appearances. Hover or focus the icon to see the current and next colors; the singer video keeps its original colors.

Open the **Preferences** gear for collapsible Appearance, Library Settings, Karaoke Services, Shared Karaoke Nerds Catalog, Video Downloads & Karaoke Nerds Cache, Queue Management, Audio Controls and Singer Display groups. Karaoke Services shows the status of the planned paid-provider connections; account linking is not yet available. **Rotate singers fairly** gives each singer a turn before their next song; when unchecked, songs follow request order. A staged song remains locked until released or removed. Switching approval mode affects new requests only. Playback volume also appears below the transport; Singer Display can show upcoming singers and a host-selected PNG/JPEG logo. **Open singer display fullscreen** applies when the display is next opened; the host fullscreen icon affects only the current window. The host may limit each singer’s pending, accepted and staged future requests; playback and existing requests are not removed if the limit is lowered.

**Video Downloads & Karaoke Nerds Cache** lets you choose a permanent base folder and optional yt-dlp executable; blank uses your Videos folder and PATH discovery. yt-dlp and FFmpeg must be installed. Existing files stay where they are after a folder change. Mapped brands use `BASE/karaokenerds/Brands/BRAND_SLUG/ARTIST/ARTIST - TITLE.mp4`; ordinary links use `BASE/youtube/ARTIST/ARTIST - TITLE.mp4`. Retain ownership sidecars for verified reuse. Brand/artist automatic caching is still planned; its saved selections do not start batch jobs. See [download details](docs/youtube-downloads.md).

**Pause Interval** sets a 0–300 second gap after a song completes or is skipped. You may stage the next song during the gap; the host must press Play after the countdown, so there is no automatic playback. Pause, resume and stop do not begin a gap. The deadline survives restart and elapsed time while the app is closed counts. The default is zero.

**Bumper music** is an experimental host-controlled feature in Audio Controls. Open the singer display and save an explicit audio output first; the system-default choice is unavailable for bumper playback. Choose from three locally generated instrumental themes or add up to five of your own MP3, M4A, WAV or OGG files. Start and stop music manually; it continues through the list until stopped or karaoke starts. It does not start automatically after a song, at launch, or after an output change. Removing a custom entry does not delete the source file. Supported containers still depend on available codecs. Audio output and transitions require physical testing before live use.

Preferences are saved in `settings.json` in Electron's user-data directory. Use **Configuration Files** to reveal it or `keybindings.json` in the file manager; hover for the full path. Close the app before editing either file and restart to apply changes. Settings include appearance, `accentColor` (blue, pink or purple), layout, auto-approval, rotation mode, filename fallback, ordered `metadataTemplates`, master volume, output device, pause interval and singer-display options. Missing fields use defaults; invalid values or unknown fields are rejected. Back up these files with the show database.

Filename templates apply to new imports in priority order. Examples include `${DJ Code} - ${Artist} - ${Title}`, `${Track Number}.${Artist} - ${Title}`, `${Artist}/${Track Name}.mp4` and `${Title} - ${Artist}`. Fields cannot be repeated or adjacent without a separator; use `/` between folder components. Ambiguous matches are marked for metadata review. If nothing matches, the fallback format is used. Right-click and choose **Edit Metadata** to correct a local entry. Embedded tags are not read or written yet; originals remain unchanged.

## Verify

```bash
npm test
npm run build
./scripts/make-rehearsal-fixture.sh /tmp/tpv-rehearsal-fixture.mp4
xvfb-run -a node scripts/rehearsal-smoke.mjs /tmp/tpv-rehearsal-fixture.mp4
node scripts/interaction-smoke.mjs . /tmp/tpv-rehearsal-fixture.mp4
```

The fixture script needs FFmpeg with H.264/AAC encoders and refuses to overwrite an existing file. The smoke scripts need a graphical session (or Xvfb on Linux), use isolated temporary profiles and mute audio. They cover import, requests, queue removal, playlists/history, transport, display closure, forced termination and recovery. They do not verify speakers, an external mixer, HDMI hot-plug or audio-device failure. Delete the synthetic fixture when finished.

## Current boundaries

- Local MP4 and converted MP3/CDG karaoke, plus permanent YouTube downloads for the normal show queue. Key/tempo is not implemented. Import hashes files in a worker without copying them; actual large-library, network-drive and Dropbox behavior still needs testing. Experimental bumper playback has no fade or automatic intermission scheduling. Audio output selection has automated coverage but requires physical device-loss verification.
- Library metadata comes from configurable filename parsing and local host edits; embedded tags, write-back, alias indexing and detailed version information remain planned. Ratings and policy are domain foundations, not a finished host policy interface. The experimental local singer page exposes a policy-filtered guest catalog.
- Queue moderation, simple rounds, staged lock, manual reordering, request edits, timed singer absence/return, generation checks and SQLite recovery are implemented. Indefinite holds, duets/groups, wait estimates and fuller show management remain work.
- The general local API, connected companion apps, internet relay, profiles, paid karaoke-provider integrations and billing are not implemented. The shared Karaoke Nerds service is deployed with dedicated MySQL storage and a tested server backup/scratch-restore path. The Windows desktop client has passed live HTTPS status/search and durable offline-cache checks. Actual show hardware and catalog-to-download operation still need verification. The experimental singer-only HTTPS service is off by default and opens only when the host explicitly starts a local room.
- Night, Day and system theme work in the host; the singer display keeps source video colors unchanged. A full accessibility and multi-platform audit is still needed.

See [current handoff](docs/handoff.md), [product review and work list](docs/feature-review.md), [architecture and progress](docs/architecture.md), [roadmap](docs/roadmap.md), and [provider research](docs/provider-research.md).

The bottom playback timeline supports dragging or keyboard seeking, elapsed/remaining time, and 10-second rewind/forward. Paused seeks stay paused; acknowledged positions restore paused after restart. See [playback controls](docs/playback-controls.md).

In Singer Rotation, drag accepted waiting rows or use Move up/down and the right-click menu. **Automatic order** resets manual scheduling. Right-click a waiting request to edit its track or singer; staged/playing songs are protected. Singer changes get the recipient’s next available round while keeping an explicit manual slot. See [queue management](docs/queue-management.md).

In Singers, mark someone unavailable for 1–60 minutes, or select **Return now**. Their existing place becomes eligible on return without displacing a staged song or autoplaying. Unavailable singers may have one future request; existing extras are retained but block additions. Local singers can control their own availability. See [availability](docs/singer-availability.md).

Use **Import CD+G / ZIP…** for a matching MP3/CDG pair or one pair in a ZIP. FFmpeg on PATH converts it to a managed MP4; originals stay unchanged. This takes additional space and managed videos need separate backup. See [CD+G import](docs/cdg-import.md) for limits and setup.

The catalog client configuration contains only the service origin and a scoped client token; the Karaoke Nerds upstream key and MySQL credentials stay server-side. It is supplied separately from packages. A private host configuration has been provisioned in the app data directory with a protected backup under `C:\tmp`. Local catalog fallback is used when shared access is unconfigured or disabled; a configured service error is reported rather than silently switching catalogs. See [catalog operations](docs/karaokenerds-catalog.md) for the refresh hold and recovery limits.

# Experimental local-network singer requests

Remote queueing is off at startup and after restart. The host can explicitly open one experimental local-network room in **Preferences → Remote Queueing**. Internet access is not available; it requires a separate relay. The local workflow has automated loopback coverage but has not been verified with actual venue networks or physical phones and is not yet live-show-ready.

## Open a room

1. Prepare a private IPv4 network interface, a hostname that resolves only to that interface, and a matching, currently valid TLS certificate and private key. The certificate must chain to a trust root accepted by the app's Node runtime and by singers' browsers. The app does not provision or renew certificates, configure DNS or change the firewall. Phone trust can differ from Node's trust; never ask singers to bypass certificate warnings.
2. In **Preferences → Remote Queueing**, choose the interface, enter the lowercase certificate hostname and port, and use the native pickers to select the certificate and private-key files. The host sees only filenames; the key contents and file paths stay in the main process. Click **Open local room**. No listener is opened until that action.
3. Choose an invitation lifetime and click **Create invitation**. Share the displayed link privately with the singers you want to admit. Anyone with the link may join while it is valid. Invitation secrets appear only in the link fragment and are not persisted by the panel; the panel clears the link on expiry, room close or invitation revocation.
4. Singers connect on the venue network, enter their names, browse and request available songs, or send a missing-song request. Normal approval and rotation rules apply. The host sees joined guests, can revoke an individual, and can review unavailable-song requests in **Requests**. Mark each request Pending, Reviewing, Fulfilled or Declined; statuses are private to the host and survive restart. A missing-song request does not add media or enter the rotation.
5. **Revoke invitations** prevents new admissions but leaves previously admitted singers connected. **Revoke access** blocks an individual guest. **Close room** stops the listener and revokes all invitations, sessions and resume credentials. The room does not reopen automatically after restart; create new invitations for a new room.

The host guest list is limited to 200 unexpired, unrevoked entries. Singer access is held only by the open browser page; when a singer closes that page, they need a fresh invitation. If a room reports a cleanup failure, use **Retry closing room** and do not assume it is closed until the status confirms it. If the host or browser cannot validate the certificate or resolve the hostname, fix provisioning rather than weakening TLS.

## Developer boundaries

The guarded host bridge selects opaque TLS file handles and opens the LAN provider only on the host's explicit command. A single SQLite authority installs committed guest mutations in host state before broadcasting; stale state cannot be written after a failed installation. The singer page and its allowlisted assets are served on the exact same HTTPS origin with restrictive CSP. The API requires the expected Host and Origin, scoped bearer credentials and bounded requests. Paths, host-only data and media URLs are not guest-visible.

On close, listener shutdown and credential revocation are both attempted; a partial failure retains a recovery handle and blocks reopening. During app shutdown the Store gates guest operations and the lifecycle aborts startup or the active room, then waits up to five seconds for cleanup. If cleanup remains unfinished, the process exits without closing the Store underneath pending work. A later room revokes stale credentials before opening.

Automated tests include an isolated Electron run with a disposable profile, a test-only certificate and a loopback-redirected interface; browser and API guests joined, requested songs, submitted missing songs and were revoked. This does not verify actual device trust, venue DNS, public certificate renewal, unplug/firewall behavior, native platforms or an internet relay. Continue the security, abuse and physical-device checks in [remote queue design](remote-queue-design.md), [LAN provider](remote-lan-provider.md) and [local HTTPS transport](remote-https-foundation.md).

# YouTube streaming

YouTube recordings can be added to the host's Song Library from **Karaoke Nerds** or by entering a normal YouTube video link, title and optional artist there. Adding the same video again selects its existing library entry. No YouTube API key or subscription is needed for these direct video links or for the existing saved Karaoke Nerds search. General YouTube search is not implemented.

The library shows **YouTube** where local entries show their DJ/track code or Local. Select a singer and request the recording through the same dialog used for a local song. Streaming requests follow approval, content policy, rotation and history rules. They retain the exact video ID and are not downloaded. Private or unavailable videos, disabled embeds, ads, region restrictions and network failures can prevent playback.

Open the singer display and use the host's normal Play/Pause, Stop, Skip, volume and timeline controls. The official YouTube player is visible in the singer display with its native controls and attribution. Playback requires internet. Start or resume may need time to load. A failed start leaves the request available; errors during playback pause the show rather than completing a singer's turn. Stop returns it to the waiting queue; Skip deliberately consumes the turn. Restoring a show never automatically resumes a song.

YouTube uses the operating system's audio output. The device chosen in Preferences for local files does not route the embedded player. When a particular local output is configured, the host must acknowledge this difference before the first YouTube playback in a session, and again after changing that preference. Check system routing to the mixer before using YouTube in a show. Muted test playback does not verify that routing or audible output.

Hiding or minimizing the singer display mutes the embedded player and pauses the show. Restore it and explicitly resume. Closing or losing the display also pauses playback. Buffering for 30 seconds pauses with a recovery message. A separate preview remains available, but it cannot overlap show playback or bumper music. YouTube's required controls are not hidden, and videos are not substituted when the original cannot play.

The player runs in a separate sandboxed WebContentsView with no preload, Node integration or application IPC. It receives only the selected video ID, public performance caption, volume and playback commands. A tokenized loopback page loads the official IFrame API. Only fixed numeric seek/state operations are executed in it. The main process checks the active generation before accepting timing, completion or native play/pause events. Configured Search and Play/Pause shortcuts are handled through the host authority when this view is focused.

The development player supplies the app's reverse-domain identity in the embed Referer, as required for desktop integrations. Distribution still needs installation/app-identity review and real-device/venue checks. The user's YouTube account is not connected; the isolated player session has no persistent sign-in storage. User interactions with YouTube may be subject to YouTube's normal terms and third-party privacy behavior.

Validation: `node scripts/streaming-smoke.mjs` after rebuilding uses an isolated temporary profile and muted audio. It adds the official IFrame API sample as a test song, plays the real remote embed, pauses, seeks while paused, checks safe minimization and explicit recovery, stops without consuming the request, and checks persisted source identity after restart. It does not exercise paid providers, real karaoke recording availability, speaker/mixer routing, ads or every network failure. Parser/domain/page tests are in `tests/domain/streaming-source.test.ts`.

References: [IFrame API](https://developers.google.com/youtube/iframe_api_reference), [embedded-player minimum functionality and desktop identity](https://developers.google.com/youtube/terms/required-minimum-functionality), and [provider access research](provider-research.md).

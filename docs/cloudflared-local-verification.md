# Cloudflared local verification

This is a development verification procedure, not an enabled internet feature. The app does not download, install or start `cloudflared` automatically. On 7 November 2026, no `cloudflared` executable was found on PATH, in the repository, or in the checked common Windows Program Files, Chocolatey and Scoop locations; other locations were not exhaustively searched. A standalone official Windows x64 executable was subsequently downloaded into the separate `karaoke-windows-verify` workspace for a bounded compatibility check, not installed or added to PATH. Its SHA-256 matched Cloudflare's published value. No public tunnel was created.

Cloudflare's [download page](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/downloads/) points Windows users to its GitHub releases. The official [2026.10.7 release](https://github.com/cloudflare/cloudflared/releases/tag/2026.10.7) lists the SHA-256 for `cloudflared-windows-amd64.exe` as:

```text
2493dbc168923bb3e59e5e7716f71deced92992eea9acd6e9d74f84ac7751343
```

`src/main/cloudflared-integrity.ts` provides an **unconnected, offline** checker for this pinned release's Windows x64 executable. It checks an absolute selected path, regular-file metadata, size, and file bytes against the app-owned digest, and rejects symlinks and files changed while read. Its second argument exists for trusted main-process release data and test fixtures; never accept a digest supplied by a singer or renderer. Tests use synthetic bytes and do not execute a program. A hash match establishes that the inspected bytes match the specific digest; it is not an automatic software update policy or proof that a subsequently executed path still names the same bytes. A process with access to the file could replace it after inspection. Before integration, bind verification and execution using an appropriately protected, app-controlled location and a platform-specific replacement/race policy; review what guarantees that location actually provides.

For a future local compatibility check, use a binary obtained through Cloudflare's official channel and verify its digest against the specific version's official release notes. For example, on Windows, `Get-FileHash -Algorithm SHA256 -LiteralPath <selected-file>` computes a hash without starting the program. Do not paste credentials or private keys into commands or logs. The development supervisor accepts both `cloudflared.exe` and the official `cloudflared-windows-amd64.exe` release filename; its acceptance of a name does not verify the file's contents.

After checksum verification, the isolated executable's `--version` reported 2026.10.7, and `tunnel --help` listed the supervisor's `--config`, `--no-autoupdate`, `--url`, `--origin-server-name` and `--origin-ca-pool` flags. The [upstream source for 2026.10.7](https://github.com/cloudflare/cloudflared/blob/2026.10.7/cmd/cloudflared/tunnel/quick_tunnel.go) contains the announcement text recognized by the prototype. These checks do not prove the supervisor's combined command, config-file isolation, process lifecycle or origin TLS behavior; those require an isolated functional test.

Cloudflare's [Quick Tunnel documentation](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/) describes temporary publicly reachable development URLs and explicitly limits them to testing and development. Any actual public test requires an explicit host action, an independently reviewed authenticated guest router, isolated scoped credentials, an appropriately trusted loopback CA and matching certificate, safe shutdown, and outbound [port 7844](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/configure-tunnels/tunnel-with-firewall/) connectivity. Do not run such a test until those pieces are ready. Browser trust, public routing, outage and revocation, and real-device behavior remain unverified.

# Remote singer page foundation

The React page in `src/remote/SingerPage.tsx` is a prototype component. Vite now builds a singer entry and a manifest, but the desktop app does not host the page and singers cannot yet reach it. Host controls, a trusted HTTPS listener integration, an invitation workflow, and an internet relay are still required before both local and internet remote use can be offered. The existing host-authority and security requirements in [remote queue design](remote-queue-design.md) still apply.

The page allows a singer to join by name, browse paginated policy-filtered songs supplied by the authority, request a loaded song, and see their own request statuses. The search covers loaded pages; a singer can load more. It labels a truncated recent request history. It refreshes periodically and offers manual reconnect using an in-memory resume secret. Its missing-song form submits a title and optional artist for the host to review; this does not add the song to the rotation. The authority derives the singer from the authenticated guest and persists the request and receipt atomically. These controls remain unusable until the page and service are integrated.

The `invite` fragment is removed from browser history immediately, and admission, session, and resume secrets stay in page memory and out of URLs. Closing or reloading the page loses access and requires a fresh invitation. A lost join response is retried with the same identity. If a request response is uncertain, the page blocks further requests and checks its original outcome rather than automatically resubmitting. If a catalog revision changes between pages, it refreshes instead of combining stale pages. None of these client checks replaces server authorization or transaction rules.

The fetch adapter permits only same-origin HTTPS, supplies no cross-origin or insecure fallback, sends sessions in the authorization header and does not send cookies. A future server must enforce the documented Host/Origin validation, rate and body limits, secure hosting headers, invitation/session lifecycle and authorization. Tests cover client state and transport construction, not browser security, real network interruption, relay behavior, accessibility on mobile devices, or physical venue Wi-Fi.

`createSingerStaticHandler(buildRoot)` in `src/main/remote-static.ts` is an unconnected handler for a future HTTPS server. It reads only the singer entry and its transitive Vite manifest dependencies into a fixed allowlist, rejects query strings on singer/asset routes, and serves `/singer/` and listed assets with a restrictive same-origin CSP, no-store, nosniff and no-referrer headers. It never takes a filesystem path from an HTTP request, and rejects manifest paths that escape the build directory. It does not open a listener, validate a request's Host or establish TLS; the owning server must do so before invoking it. Top-level browser navigation does not necessarily include an Origin header, whereas API requests retain the stricter Origin check. A fragment invitation remains client-side and is cleared immediately; do not put credentials in request paths, queries or logs.

## Product direction and decisions

- The desktop host is the authority for playback, the durable queue and the current show. A party and a show are the same session. Local hosting must work without internet access. Hosts or venues will eventually pay; singer participation is free. Prices, plans and limits remain undecided. The marketing site and branding guide are separate projects.
- New song requests default to **automatic approval**. The host can choose moderation. This supersedes the original handoff's moderated-by-default decision. Switching modes affects new requests; existing pending requests are not silently approved.
- Hosts should be able to edit artist and title locally and choose **per edit** whether supported embedded file metadata should also be changed. Local-only is the default. No import, rescan or ordinary local edit should implicitly modify source media. If an explicitly requested embedded write fails or is unsupported, report that outcome and retain the local edit. The per-edit choice and embedded write-back are **not yet implemented**; the current edit only changes the local database.
- Preserve the accepted mockups and the original handoff's domain, playback safety, privacy, security and accessibility requirements. The requested work list extends those requirements; it does not turn planned features into implemented features.
- The 13 November owner-selected provisional identity is **Microphone Play** (`mic-play`): a vintage microphone with a play outline, using orange `#F68713`, pink `#ED0D63`, navy `#131457` and gray `#E9E9E9`. It supersedes Velvet Script. The application icon has no visible text; the full logo reads **TPV / KARAOKE BOOTH**, correcting the extra E in the reference. The default installed icon is the original navy mark on a white rounded tile; matching dark/light masters and exports are retained. All 69 generated hashes and actual Windows package/installed icon resources passed. Assisted installer artwork and theme-selected host logos are integrated. Preserve earlier explorations and licenses as history. See the [branding source and reproduction instructions](../assets/branding/README.md). No native Mac build is claimed.

## Important remaining boundaries

- Embedded tag reading and the per-edit file-write choice are not implemented. The [metadata write-back design](metadata-writeback-design.md) records the default-off choice and recovery requirements. MP3/CDG pairs and single-pair ZIP import convert through external FFmpeg to managed MP4; timeline seek and elapsed/remaining time exist. Automatic bumper scheduling is implemented as an opt-in experimental feature; pitch/tempo, fades and physical verification remain work. Moved MP4s can be relinked only to a byte-for-byte match; full hashes are checked on start. Genre browsing is a placeholder.
- Hosts can create a checked show database snapshot via **Back up show…**; the save destination must be new and support hard links. Cleanup failures retain a retry action and report whether publication occurred. The database includes private singer and library-path data; destination permissions are inherited. Videos, settings and other external files need separate backup. The app has no live restore flow. The main process tracks the picker and operation through shutdown. See [show database safety](show-database-safety.md).
- Import hashing runs in a worker, reports individual results and can be cancelled without removing songs already committed. Results are in memory until the next import or app exit. The isolated Windows rehearsal covers playback pause during a deliberately slowed import and shutdown/restart; real large libraries, network drives and Dropbox still require testing. See [import jobs](import-jobs.md).
- Singer-display fullscreen requests are serialized across native window transition events; the saved preference takes effect on the next open and the host toggle affects the current display. A muted Electron rehearsal tests fullscreen, exit, reopen and playback pause on window loss; physical monitor disconnect and macOS window-manager behavior remain unverified.
- Experimental bumper playback uses three generated themes and up to five host-selected audio files, requiring an explicit output and open singer display. Optional automatic between-song playback defaults off and retains the chosen theme. It starts only after natural completion or confirmed skip and an authorized display confirms karaoke silence; pause, Stop, launch and device recovery do not start it. Muted full smoke passed; audible output, transitions and mixer behavior require physical testing. See [bumper playback design](bumper-playback-design.md).
- Shared user profiles, the full Host/Co-host/Moderator/Singer/Audience permission model, companions, paid karaoke-provider integrations and billing remain unimplemented. The initial local API/CLI source is wired behind an off-by-default preference for capabilities, state, settings and shortcut reads plus queued Preferences/Keyboard Shortcuts navigation; the actual Windows app and compiled CLI passed the private-profile integration rehearsal; Windows and Linux bundled-wrapper/package checks passed.

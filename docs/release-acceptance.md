# Release acceptance

Use this checklist for development releases and before approving **1.0.0**. Record the version, commit, platform or phone model, test result and issues. Use a disposable show or a verified copy of an existing show. Keep account and room credentials out of test evidence.

## Development release checks

- [ ] Verify the published manifest, install packages and checksums against the candidate commit. Confirm the latest download redirects and the associated release notes. Record which platform builds passed and which installers were actually exercised. [Downloads](https://release.thepropervolume.com/booth/)
- [ ] Rehearse an upgrade from the previous supported version and a fresh install in separate profiles. Verify the show, media links, history, settings, shortcuts and CLI still work. On a migration, check the standalone pre-upgrade backup and confirm a simulated failure leaves the older database usable. To roll back a migrated show, use the pre-upgrade snapshot with the compatible app version. [Database safety](show-database-safety.md) · [CLI guide](local-api.md)
- [ ] Back up a populated show, make changes, and restore the backup through **File → Restore Show Backup…**. Verify preview, cancellation, rollback snapshot, remote room closure, retained queue and a quiet restart with any interrupted song paused. Verify a failed restore leaves the current show usable. Back up media and settings separately. [Database safety](show-database-safety.md)
- [ ] Import known MP4, CD+G and LRC fixtures. Check artist/title matching from the original filenames, including accents and duplicate names. Move a fixture, reject a different recording, relink the exact original, and play it from the queue. Exercise decoder failure, pause and deliberate recovery. [Import jobs](import-jobs.md) · [Paired lyrics and audio](cdg-import.md)
- [ ] Open a disposable remote room. From a separate singer browser, find a song past the first search page, request it, and withdraw it before playback starts. Check reconnect, permission denial, private screen access and revocation when the host ends the room. Confirm the production room count before any relay restart. [Singer guide](singer-guide.md) · [Screen sharing](singer-screen-sharing.md)

Repeat the affected cases on the exact candidate build and record hardware results separately. [Remaining work and build evidence](remaining-work.md)

## Official release gates

- [ ] Install, upgrade and uninstall on supported Windows, Linux and macOS systems. Verify signing and launch behavior for the intended public distribution and cover both supported Mac architectures. Rehearse rollback against a copy of a representative show. [Handoff](handoff.md)
- [ ] Rehearse a show on the intended audio mixer, output device and external singer display. Check audible vocals and backing audio, bumper and applause levels, mute and output routing, HDMI or USB device loss and reconnect, fullscreen, and deliberate recovery without autoplay. Complete songs from representative real local codecs and lyric formats, and record what the equipment actually played. [QA test guide](qa/qa-test-guide.md) · [Screen sharing](singer-screen-sharing.md)
- [ ] Confirm the store publisher and app identities, activate Apple and Google developer accounts, and build with the owner's signing keys. Run TestFlight and Google Play testing on real iPhones and Android phones. Check playback, LAN discovery permissions, Piggyback admission, Full Host, background and resume, and guest photo approval. Complete privacy forms, support links, moderation and content disclosures before public submission. [iOS guide](store-ios.md) · [Android guide](store-android.md) · [Data inventory](store-data-inventory.md)
- [ ] Run a host and multiple guests on the actual venue network and from the public internet. Check session recovery after a network break and a long rehearsal, private-screen latency and revocation, and usable local playback during a catalog or relay outage. [Remote client guide](remote-singer-client.md)
- [ ] Verify production Karaoke Nerds search and a permitted complete recording download from an installed app. Test monitoring and recovery on a disposable catalog copy. Keep refresh disabled until previous refresh history is reconciled and a single daily worker has been verified. Record the current snapshot age, query load, and rollback procedure. [Shared catalog guide](shared-catalog.md)
- [ ] Confirm the service agreement and allowed account types, distribution, territory, venue use, offline use and play reporting for each paid provider included in the release. Test full songs, expiry and recovery with each approved account type. Describe search-only sources accurately in the app and store listing. [Source status](source-status.md)

Approve 1.0.0 after the applicable gates are recorded for the exact release build and the owner signs off on any deferred features. [Product specification](product-specification.md)

# Windows Firewall Inspection — 15 November 2026

The owner's Windows session showed all three active network adapters classified **Private**, with no Azure AD, enterprise, domain or workplace enrollment reported by the inspected system status. The checked firewall Group Policy/MDM/UI-policy registry locations were absent. Two local inbound `electron.exe` **Block** rules applied only to **Public** networks. The process was not elevated; UAC was enabled. Effective firewall profiles were Private/Domain disabled and Public enabled, with inbound blocking and listen notifications enabled on Public. These are observations from that session, not settings changed by TPV.

The exact source of the yellow **“This setting is managed by your organization”** label was not established. This evidence does not justify claiming the computer belongs to an external organization or resetting Windows security policy. Microsoft documents that cancelled or non-administrator prompts can create TCP/UDP block rules, and that explicit blocks take precedence over allows: [Windows Firewall rules](https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/windows-firewall/rules). The two rules are consistent with that documented behavior; their creation history was not recovered.

The app previously opened optional singer-screen sharing on a wildcard address. Version 0.7.0 instead binds individual verified Private Windows interfaces and loopback. Failed classification permits loopback only. The real discovery check found three approved private IPv4 interfaces and no wildcard binding. Trust is checked on retry and periodically; withdrawn interfaces lose their listeners. This narrows the app's exposure, but is not proof that every Windows notification is resolved.

No firewall rules, adapter categories, security policies or enrollment settings were altered. Install the current build and use **Remote Sessions → LAN Singer Screens → Refresh Addresses** for the active links. `127.0.0.1` works only on this computer. Local host playback and outbound internet request sessions do not require this optional inbound visual-sharing port.

# Background import job foundation

`ImportJob` is an unconnected main-process foundation for progress, cancellation and per-file results. The current desktop import flow has not yet been replaced by it. The helper opens no file picker, modifies no media and does not own show state or SQLite. It accepts only absolute paths supplied by trusted main-process picker code; never expose path selection or the commit callback to a renderer.

One job at a time scans selected MP4 files or folders. Folder enumeration is asynchronous, ignores non-MP4 files and does not intentionally follow discovered symbolic links. Each MP4 is hashed in a worker thread, keeping the host authority and playback controls responsive. The worker checks file identity, size and timestamps before and after hashing and rejects an observed source change. This is not a filesystem lock and cannot eliminate a concurrent writer's race after the final check; do not claim it protects against arbitrary external modification. The worker reports bytes read for the current file and is terminated on cancellation. No original media is moved or deleted.

The trusted synchronous `commit(path, fingerprint)` callback must check duplicates and atomically persist the resulting show state and private media record before it returns `imported` or `duplicate`. It may mark an imported song for metadata review. Once a synchronous commit begins it completes before cancellation can interrupt the main thread; an already committed song remains imported. Cancellation during hashing records that active file as cancelled, stops the worker and does not commit it. Files that have not yet been discovered have no result. The completed, cancelled, duplicate, failed and review counts reflect the results actually recorded.

`start()` returns a job snapshot immediately; `snapshot()` and progress notifications expose counts and the current filename/byte progress, not absolute paths. Folder totals are not known in advance because scanning and processing are interleaved. `page(jobId, offset, limit)` returns at most 100 per-file or directory outcomes at a time. Results currently live in memory only: they remain available until another job starts or the app exits. A host-facing implementation must make that retention limit clear and avoid claiming durable import history. A result does not imply that an MP4's codecs are playable.

## Wiring requirements

- Subscribe the host window to job progress before requesting its snapshot, guard every operation against the actual host window, and expose cancellation and paged results by job ID only. Paths and file data remain main-process-only. Avoid using the host's global busy state for the whole batch so transport controls remain usable.
- Use native file or folder pickers before calling `start`; retain one copy of metadata parsing settings for the batch. Keep import actions separate from playback and use the current authoritative state when each atomic commit occurs. Retain already imported songs if the job is cancelled.
- On shutdown, cancel the job and wait for its worker to terminate before closing resources it may still use. Do not close the SQLite Store underneath a pending commit. Handle worker errors and interrupted scanning without claiming an uncommitted file was imported.
- Present a compact progress indicator, current file and bytes, a Cancel button, and individually browsable results, including duplicates, failures, cancelled files and metadata-review markers. Report that remaining undiscovered files were not processed when cancelled.
- Verify the connected host UI with isolated synthetic files, cancellation, continued playback/control, duplicates, large directories, permission and source-change errors, restart and shutdown. Physical disk, network-share, Dropbox and large-library behavior remain to be tested.

Focused tests cover actual worker hashing and host-loop responsiveness, duplicate/failed/review outcomes, paginated results, cancellation during hashing and after commit, recursive discovery, symlink exclusion and an observed file mutation. A separately bundled Electron 45 test also ran a worker import. These do not establish that a video plays or that all concurrent filesystem changes can be detected.

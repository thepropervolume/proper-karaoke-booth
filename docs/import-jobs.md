# Background import jobs

`ImportJob` powers desktop import progress, cancellation and per-file results. The helper opens no file picker, modifies no media and does not own show state or SQLite. The host's main process uses native pickers and passes their absolute paths to the job; renderer IPC cannot supply paths or the commit callback.

One job at a time scans selected MP4 files or folders. Folder enumeration is asynchronous, counts and skips non-MP4 files and does not intentionally follow discovered symbolic links. MP3/CDG pairs and ZIPs use the separate CD+G import. Each MP4 is hashed in a worker thread, keeping the host authority and playback controls responsive. The worker checks file identity, size and timestamps before and after hashing and rejects an observed source change. This is not a filesystem lock and cannot eliminate a concurrent writer's race after the final check; do not claim it protects against arbitrary external modification. The worker reports bytes read for the current file and is terminated on cancellation. No original media is moved or deleted. Cloud-only files may need to be downloaded by the sync provider before hashing can finish.

The trusted synchronous `commit(path, fingerprint)` callback must check duplicates and atomically persist the resulting show state and private media record before it returns `imported` or `duplicate`. It may mark an imported song for metadata review. Once persistence succeeds, return the committed outcome even if a best-effort UI notification fails; do not report a committed song as failed and invite a duplicate retry. If authoritative state cannot be installed after a commit, stop mutations and require recovery. Once a synchronous commit begins it completes before cancellation can interrupt the main thread; an already committed song remains imported. Cancellation during hashing records that active file as cancelled, stops the worker and does not commit it. Files that have not yet been discovered have no result. The completed, cancelled, duplicate, failed and review counts reflect the results actually recorded.

`start()` returns a job snapshot immediately; `snapshot()` and progress notifications expose counts and the current filename/byte progress, not absolute paths. Folder totals are not known in advance because scanning and processing are interleaved. `page(jobId, offset, limit)` returns at most 100 per-file or directory outcomes at a time. Results currently live in memory only: they remain available until another job starts or the app exits. A host-facing implementation must make that retention limit clear and avoid claiming durable import history. A result does not imply that an MP4's codecs are playable.

## Integration and remaining checks

- The host window subscribes before its snapshot, and every import IPC operation is guarded against the actual host window. Cancellation and paged results use job IDs; paths and file data stay in the main process. The picker and active job do not hold the host's global busy state, so playback controls remain usable.
- The batch captures one copy of metadata parsing settings. Each synchronous commit uses the current authoritative show state, retains prior committed songs on cancellation and reports a successful commit even if a subsequent UI notification fails.
- Shutdown cancels the job and waits up to five seconds for termination along with remote-room cleanup. If work cannot finish in time, the process exits without closing the SQLite Store underneath pending work. A cancelled picker cannot start a new job after shutdown.
- The panel shows folders scanned, non-MP4 files skipped, current-file bytes, a Cancel button, counts and paged results, including duplicates, failures, cancelled files and metadata-review markers. Failures distinguish missing, permission, unavailable, empty and changed files where the system provides a reliable category, without exposing absolute paths. It states that undiscovered files were not processed and that results are retained only until the next import or app exit.
- Isolated Windows Electron rehearsals cover synthetic media, duplicate and empty files, cancellation, playback pause during a deliberately slowed worker, and shutdown/restart. A packaged Windows 0.2.0 rehearsal with a disposable verified profile and synthetic files imported two nested MP4-named fixtures through the folder picker; those files were not decoded or played. One real MP4 in the reported Dropbox folder was also fingerprinted successfully in a bounded read-only check. A later full real-folder run reproduced all-file changed errors, followed by a successful retry. Bounded new full checks now handle that condition; the final packaged 0.3.0 app imported all 237 actual MP4 files into a disposable library with zero failures in about eight seconds. A separate run injected an initial changed error on every file and then persisted all 237 after fresh hashes. Original media and the real show remained unchanged. The exact transient Windows/cloud metadata cause, other files, network shares and genuinely large libraries remain unverified.

Focused tests cover actual worker hashing and host-loop responsiveness, duplicate/failed/review outcomes, paginated results, cancellation during hashing and after commit, recursive discovery, symlink exclusion and an observed file mutation. A separately bundled Electron 45 test also ran a worker import. These do not establish that a video plays or that all concurrent filesystem changes can be detected.

## Host panel foundation

`src/renderer/ImportPanel.tsx` uses the host-only `status`, `subscribe`, `cancel(jobId)` and paginated `results(jobId, offset, limit)` bridge. It subscribes before reading the initial snapshot and ignores stale page responses when a job changes. `onActiveChange` disables the two import actions while a job runs but does not disable playback controls. The panel does not start jobs or receive source paths. Server-rendered tests cover accessible status/progress markup and completed/cancelled wording; a browser rehearsal exercises subscription races, cancellation and pagination. More physical accessibility and responsive-layout testing remains useful.

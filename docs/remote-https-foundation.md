# Local HTTPS transport foundation

`src/main/remote-https.ts` is an isolated, opt-in transport for an injected guest authority and an optional allowlisted singer page handler. It is **not connected to the desktop application** and is never started on application launch. Internet queueing is not provided. It exposes no host, playback, administrative, filesystem, or media operations.

An integrator must deliberately choose a specific private, link-local or loopback interface, browser-visible hostname, port, and a certificate/key pair. The listener refuses wildcard and public addresses. It checks the certificate's date and that it covers the hostname; the caller is responsible for obtaining and maintaining a certificate that guest devices actually trust and for resolving that name to the selected interface. A self-signed certificate will ordinarily fail on phones. TLS failure must never trigger an HTTP fallback or instructions to bypass browser warnings.

All API operations are same-origin JSON POSTs under `/api/v1/`; `Host` and `Origin` must exactly match the configured HTTPS origin. No CORS permission is returned. Admission and join accept the invitation in the body, and subsequent guest operations require the session in the `Authorization` header. Inputs and responses are bounded, with an explicit connection limit, socket timeouts, and rate limits by source socket address; source-provided forwarding headers are ignored. A host-supplied error callback receives unexpected listener failures and the server stops accepting connections. The host chooses when to close the listener. An integrator may explicitly pass the built-page handler from `createSingerStaticHandler`; the transport checks exact Host before serving its allowed GET routes. Browser navigation may omit Origin; when present on a GET, it must match. API requests always require exact Origin. GET bodies are rejected. The page and API share the same HTTPS origin. Do not expose secrets through paths, query strings, server logs, analytics or redirects.

This is not sufficient for production remote access. Before connecting it to the app, complete host authority integration and fail-closed recovery, host controls and room lifecycle, further static content and browser security review, comprehensive abuse and concurrency testing including sustained slow requests, trusted certificate provisioning, revocation/restart integration, and real iOS/Android, firewall and network tests. Per-address throttling is a basic bound, not protection against a distributed attack. A separate authenticated internet relay and its hosting, privacy, outage and recovery design are still required.

The certificate and private key in `tests/fixtures/tls` are **public, self-signed test fixtures only**, intentionally checked in so the tests do not depend on an OpenSSL installation. They must never be used for a real listener. The transport tests explicitly trust this fixture only inside isolated loopback tests; guest browsers receive no such trust configuration.

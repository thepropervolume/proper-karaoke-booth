# CD+G and timed lyrics import

Use **Import CD+G / LRC / ZIP…** in Song Library. Choose an MP3 or CDG and place its partner in the same directory with the same filename stem, or choose a ZIP containing exactly one such pair in the same archive directory. Matching is case-insensitive; duplicate matching names and multi-song archives are rejected rather than guessed.

For LRC, select a UTF-8 `.lrc` file or its same-name MP3, WAV, FLAC, M4A, AAC, Ogg, or Opus audio file. The pair must be in one folder. FFmpeg with libass and FFprobe render timed lines into an MP4 with the same backdrop choice. Enhanced timing is rendered at line level. ZIP import remains available for one MP3/CDG pair.

This implementation converts the pair into a managed H.264/AAC MP4 before adding it to Song Library. It uses the [FFmpeg CD Graphics decoder](https://github.com/FFmpeg/FFmpeg/blob/master/libavcodec/cdgraphics.c), and requires `ffmpeg` on PATH with CD Graphics, H.264 and AAC support. FFmpeg is not bundled in the app installer. Conversion is in a separate process; its progress and Cancel action are available while the host keeps using the application. Packaging and FFmpeg distribution/licensing remain release work.

By default, new CD+G imports use **TPV Animated Backdrop (Version 3)**, the supplied TPV video, looping silently behind the graphics. The bundled copy is optimized for playback; the original asset is unchanged. In **Preferences → Singer Display → Lyric Backdrop**, choose the TPV default, **Custom Video** (an MP4), or **Solid Background** to retain the source's original flat rendering. Save before importing. That preference also applies to new LRC conversions. Ordinary video songs keep their own picture.

The backdrop is composed into the managed MP4 at import time. Changing this preference does not rewrite or change existing converted songs: reimport their original pair or ZIP to use a different backdrop. Branded/custom output is 1280 × 720; the original CDG graphics proportions are retained in a centered layer. The source screen's memory-preset background and border are transparent over the video. Only the MP3 supplies output audio, even if a custom backdrop contains sound. An unavailable or undecodable selected backdrop fails the import with an instruction to change or disable it and retry; no incomplete song is added.

The source pair or ZIP is left unchanged. The completed MP4 is stored under the application's `cdg-library` data directory and then uses the same request, rotation, singer display and transport as other imported videos. Filename metadata is parsed from the original pair name (or archive entry), using the library parsing settings captured for this import. Conversion takes additional disk space; it is not native, on-the-fly CDG rendering. Show-database backups do not include these managed videos. Preserve the application data directory along with other media when moving a show.

Limits are 256 MiB for MP3, 32 MiB for CDG and 288 MiB for a ZIP, with at most 1,000 archive entries. Encrypted, unsupported-compression, unsafe-path and symbolic-link archives are rejected. Only the selected pair is extracted into fixed filenames, expanded size and CRC are checked, and malformed CDG packet lengths are rejected. Conversion is bounded to 30 minutes and extends the final graphics frame to cover audio (up to two additional hours). An intermediate alpha-mask CDG stream can use up to three times the staged graphics size (96 MiB); it is removed after conversion. Tests use synthetic CDG packets and real FFmpeg decoding to cover the looping backdrop, same-RGB black foreground preservation, frame-boundary background changes, XOR drawing, palette-latched transparency, scrolling, MP3-only audio, cancellation and missing-backdrop recovery. An isolated, muted Electron smoke also checks persisted preferences and actual bundled-video pixels. Real producer files, audible synchronization and all supported operating systems still need verification.

Cancellation stops FFmpeg before removing this job's staging directory and never adds an incomplete asset. Both cleanup branches check the original directory identity and canonical parent; a replaced directory or junction is left for review. Paired-source staging bounds copied bytes and checks file identity before and after copying. These checks do not promise protection against every same-user filesystem race. A completed asset is retained if database persistence throws, because the write outcome might be uncertain; this can leave an orphaned managed directory requiring later review. No automatic cleanup of complete managed videos is implemented. Import errors omit source paths and FFmpeg output. Conversion failures do not remove songs already imported.


Developer detail: compositing uses palette indexes, not a black/chroma key, so black lyrics and outlines at a different palette index from the background remain visible. The derived mask tracks the active memory-preset background and FFmpeg's per-index alpha latching; RGB and mask drawing, XOR and scrolling are decoded by FFmpeg itself. Each original 1/300-second packet becomes two grayscale palette packets and one drawing/no-op packet. Intermediate palette frames are discarded before timestamps are compressed by three and sampled at 25 fps; this prevents one-frame flashes at palette/background transitions. The 6-pixel side and 12-pixel top/bottom CDG borders are masked separately. Custom backdrops are opened with FFmpeg's MP4/MOV demuxer and local-file/pipe protocol allowlist, never as an inferred playlist or network URL. Mask opacity is represented with the CDG palette's four-bit grayscale precision. Legacy flat conversion is retained when the preference is disabled.

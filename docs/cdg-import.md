# MP3 + CDG import

Use **Import CD+G / ZIP…** in Song Library. Choose an MP3 or CDG and place its partner in the same directory with the same filename stem, or choose a ZIP containing exactly one such pair in the same archive directory. Matching is case-insensitive; duplicate matching names and multi-song archives are rejected rather than guessed.

This implementation converts the pair into a managed H.264/AAC MP4 before adding it to Song Library. It uses the [FFmpeg CD Graphics decoder](https://www.ffmpeg.org/doxygen/trunk/cdg_8c_source.html), and requires `ffmpeg` on PATH with CD Graphics, H.264 and AAC support. FFmpeg is not bundled in the app installer. Conversion is in a separate process; its progress and Cancel action are available while the host keeps using the application. Packaging and FFmpeg distribution/licensing remain release work.

The source pair or ZIP is left unchanged. The completed MP4 is stored under the application's `cdg-library` data directory and then uses the same request, rotation, singer display and transport as other imported videos. Filename metadata is parsed from the original pair name (or archive entry), using the library parsing settings captured for this import. Conversion takes additional disk space; it is not native, on-the-fly CDG rendering. Show-database backups do not include these managed videos. Preserve the application data directory along with other media when moving a show.

Limits are 256 MiB for MP3, 32 MiB for CDG and 288 MiB for a ZIP, with at most 1,000 archive entries. Encrypted, unsupported-compression, unsafe-path and symbolic-link archives are rejected. Only the selected pair is extracted into fixed filenames, expanded size and CRC are checked, and malformed CDG packet lengths are rejected. Conversion is bounded to 30 minutes and extends the final graphics frame to cover audio (up to two additional hours). Tests use synthetic data; real producer files, audible synchronization and all supported operating systems still need verification.

Cancellation stops FFmpeg before removing this job's staging directory and never adds an incomplete asset. A completed asset is retained if database persistence throws, because the write outcome might be uncertain; this can leave an orphaned managed directory requiring later review. No automatic cleanup of complete managed videos is implemented. Import errors omit source paths and FFmpeg output. Conversion failures do not remove songs already imported.
